# MinIO URL过期问题解决方案

## 问题描述
数据库中存储的MinIO预签名URL默认在1小时后过期，导致无法访问文件。

## 解决方案

### 方案1：动态生成URL（推荐）

在需要访问文件时，使用`object_name`动态生成新的URL，而不是使用数据库中存储的URL。

**修改后的代码示例**：
```python
# 在 app/services/md_file.py 中添加新方法
def get_file_with_valid_url(db: Session, file_id: int, user_id: Optional[int] = None):
    """获取带有效URL的文件信息"""
    file = MDFileUploadService.get_file(db, file_id, user_id)
    
    # 动态生成新的URL，覆盖数据库中的过期URL
    file.file_url = minio_service.get_file_url(file.object_name)
    
    return file
```

### 方案2：使用永久URL

如果您的MinIO服务是公开的，可以使用永久URL格式：
```
http://[minio-server]:[port]/[bucket-name]/[object-name]
```

**修改MinIO服务**：
```python
# 在 app/services/minio_service.py 中修改 get_file_url 方法
def get_file_url(self, object_name: str, expires: int = 3600, presigned: bool = False) -> str:
    if presigned:
        # 使用预签名URL（会过期）
        url = self.client.presigned_get_object(
            bucket_name=settings.MINIO_BUCKET_NAME,
            object_name=object_name,
            expires=timedelta(seconds=expires)
        )
    else:
        # 使用永久URL（不会过期）
        url = f"http://{settings.MINIO_ENDPOINT}/{settings.MINIO_BUCKET_NAME}/{object_name}"
    return url
```

### 方案3：定期更新URL

创建后台任务，定期（如每30分钟）更新即将过期的URL。

**实现后台任务**：
```python
# 创建 scripts/update_minio_urls.py
import asyncio
from sqlalchemy.orm import Session
from app.core.database import SessionLocal
from app.models.md_file import MDFile
from app.services.minio_service import minio_service

def update_expired_urls():
    """更新即将过期的URL"""
    db = SessionLocal()
    try:
        # 获取所有文件
        files = db.query(MDFile).all()
        for file in files:
            # 生成新的URL
            file.file_url = minio_service.get_file_url(file.object_name)
        
        db.commit()
        print(f"已更新 {len(files)} 个文件的URL")
    finally:
        db.close()

if __name__ == "__main__":
    update_expired_urls()
```

### 方案4：前端处理过期

让前端在接收到403错误时，自动请求新的URL。

**前端示例**：
```javascript
async function getFileUrl(fileId) {
  try {
    const response = await fetch(`/api/v1/md-files/${fileId}`);
    const file = await response.json();
    return file.file_url;
  } catch (error) {
    if (error.status === 403) {
      // URL已过期，请求新的URL
      const refreshResponse = await fetch(`/api/v1/md-files/${fileId}/refresh-url`);
      const refreshedFile = await refreshResponse.json();
      return refreshedFile.file_url;
    }
    throw error;
  }
}
```

### 方案5：使用CDN或反向代理

在MinIO前设置CDN或反向代理，提供永久的访问URL。

## 推荐实施步骤

1. **首选方案1**：修改API接口，返回动态生成的URL
   - 优点：安全性高，灵活性大
   - 缺点：需要修改现有代码

2. **次选方案2**：如果MinIO服务可以公开访问
   - 优点：简单，无需修改现有代码
   - 缺点：安全性较低，文件可被直接访问

3. **结合使用**：公开文件使用方案2，私有文件使用方案1

## 注意事项

1. 如果使用永久URL，确保MinIO存储桶的访问策略设置正确
2. 考虑文件访问的安全性，特别是对于私有文件
3. 监控文件访问情况，防止滥用
